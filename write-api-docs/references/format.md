# 接口文档格式参考

此格式提炼自两份“苍穹外卖”YAPI 导出文档。按目标项目和用户指定格式调整，不要求机械复刻 HTML 或 YAPI 的空栏目。

## 文档层级

```markdown
# 项目接口文档

## 模块或客户端名称

### 接口名称

#### 基本信息
Path：`/path/{id}`  
Method：`GET`  
接口描述：一句话说明用途；必要时写关键业务规则。

#### 请求参数
路径参数 / Query / Headers / Body：仅保留实际存在的部分。

#### 返回数据
说明响应载体和字段；必要时提供成功、失败示例。
```

接口很多时，可在正文前加简短目录或清单，至少列模块、接口名称、Method、Path。路径和方法应可直接搜索。

## 参数与响应表

参照原文的“名称 / 类型 / 是否必须 / 默认值 / 备注 / 其他信息”表格。为了对接清晰，可按实际材料改用以下列：

| 字段 | 类型 | 必填或必返 | 默认值 | 示例 | 说明 |
| --- | --- | --- | --- | --- | --- |
| id | integer(int64) | 是 | — | 101 | 路径参数；资源 ID |

- 请求字段的“必填”指客户端是否必须提供；响应字段的“必返”指服务端是否一定返回。可空性与二者分开说明。
- 路径参数、Query、Header、JSON Body、表单字段和文件字段分别列出，不把同名字段混在一起。
- 对数组写明元素类型并展开元素字段；对对象写明子字段。层级可用字段路径（如 `data.records[].id`）或树形缩进，保持全篇一致。
- 对枚举、日期时间、金额、分页字段写明取值或单位；原文未给出时标为“待确认”。
- 无证据的默认值、类型、长度、状态码、错误码、认证要求不要推测。空表格改写为“无”或“待确认”，视实际情况而定。

## 示例与特殊响应

需要调用示例时，给出与已核实字段一致的请求与响应。若接口返回文件、流或无响应体，应按真实行为说明文件类型、下载文件名或状态码；不要强行套用 JSON 响应表。对于统一响应包装，仅当目标系统有依据时才写 `code`、`data`、`msg`。

## 从参考文档得到的具体观察

- 原文按业务分组；每个接口固定出现“基本信息”“请求参数”“返回数据”。
- 请求可能位于 Query、路径参数、Headers、JSON Body 或 `multipart/form-data` 文件字段；这些位置不能互换。
- 响应表用缩进表示对象和数组元素；分页响应常含总数与记录数组，但不是所有项目或接口都如此。
- 原文部分描述、示例、字段类型和导出接口的返回说明为空。整理这类材料时，先核实实现；查不到就标记待确认，不把空白转写成肯定结论。
